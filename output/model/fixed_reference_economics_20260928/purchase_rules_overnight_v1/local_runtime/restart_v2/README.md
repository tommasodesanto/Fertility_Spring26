# Bounded local candidate-cap continuation

This isolated adapter continues a **terminal** local chain whose last candidate consumed the unchanged native 32-lifecycle-call/300-second case budget before yielding a model loss. It imports the lead-reviewed `restart_controller_v2.controller.install_censored_optimizer` and pins that function's source hash. The optimizer assigns such a candidate (+\infty) internally so it can try another point; the candidate has no computed loss and cannot be selected. All household, target, price-root, and native budget code remains pinned and unchanged.

The controller authenticates the original worker, search, case, and selected-postcheck receipts. It retains the original absolute four-hour deadline, subtracts old objective calls from the chain's 250-call ceiling, and starts from the verified selected point if one exists; chain 50 has no valid selected point and therefore starts from its original seed. A restart winner requires a fresh full native postcheck under the same deadline. Results go only to `restart_v2/runs/chainN`; original results are never overwritten.

Zero-model-solve checks: run `bootstrap.py --chain 48 --self-test` to exercise the exact local censored optimizer loop and saved-receipt contract, then `launch_stopped.py --dry-run` to list only eligible terminal chains and check result-path absence. `launch_stopped.py` uses one-thread child processes, a live 3 GiB memory margin, swap-growth limit, and the original eight-hour batch cap. Its `runs/{launch_contract.json,pids.json,latest_progress.json,terminal.json}` give the batch state. Launch only after lead review with `ALLOW_LOCAL_CALIBRATION=1` and all BLAS/Numba thread counts set to one; use a persistent terminal and `caffeinate -i` to inhibit idle sleep while the launcher runs.
