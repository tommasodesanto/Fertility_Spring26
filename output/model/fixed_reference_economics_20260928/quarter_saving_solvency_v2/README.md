# Quarter-saving solvency retry, v2

This is a one-case retry of the v1 quarter-saving **\(\phi=1\)** fixed-price diagnostic. Its source copies v1 and adds the existing no-negative-net-estate floor to buyer saving optimization at every age with positive death probability: \(b'\geq-(1-\psi)Q\), where the selling cost is \(\psi=0.06\). The buyer's saving floor is the maximum of that estate floor and the quarter-saving floor \(b_f+3\max(0,b_f-x)\), with \(x=A-Q\), \(A\) start wealth plus net sale proceeds, and \(b_f=-\phi Q\). The compiled kernel and Python fallback apply the same floor. Owner-stayer choices, forward transaction map, interest timing and the original soft purchase screen are unchanged.

Price **0.7152515073815459**, \(H_0=6.778473404808042\), \(N_0=1\), all ten calibrated coordinates, entry, preferences, targets, weights and fiscal rules remain fixed. Birth replacement and housing-market residuals are diagnostics; this is not a general-equilibrium solution or recalibration. The correction is redundant for the completed 80% case because its \(-0.8Q\) collateral floor exceeds the \(-0.94Q\) estate floor. The [v1 80% target table](../quarter_saving_benchmarks_v1/collected/run/quarter80/phase_b_ge/selected_root/target_fit.csv), [parameter table](../quarter_saving_benchmarks_v1/collected/run/quarter80/phase_b_ge/selected_root/parameters.csv), and [17 plots](../quarter_saving_benchmarks_v1/collected/run/quarter80/phase_b_ge/selected_root/standard_diagnostics/) therefore remain the 80% benchmark; no extra 80% solve is launched.

The driver runs one fresh 100% lifecycle solve and requires 14 target rows, 31 parameter rows and 17 standard plots, with native cohort, feasibility, renter, PAYGO and estate gates. From a fresh frozen-runtime mount, `python3 run.py --out /work/results/newrun` regenerates that diagnostic and its plots; the staged Torch launcher supplies one CPU, 24 GiB and a 20-minute cap. The v1 source hashes and failed-run receipts are pinned under `input/failed_v1/`; v1 itself is preserved.
