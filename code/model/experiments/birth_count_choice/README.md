# Joint intended-birth count experiment

**Reference:** canonical October 3 post-interest, soft-credit chain-13 input file
`code/model/parameters/best_params.py`. The complete 245-field native input object
and its 120-node grid are preserved. The experiment adds only the Boolean field
`birth_count_choice_enabled`, after normal input loading. It does not recalibrate,
reset the child-benefit parameter, alter targets or weights, or promote a result.

**Experimental economic change:** at every existing fertile age and valid family
state, households choose an intended count $k\in\{0,\ldots,3-n\}$. Realized
births are $X\sim\mathrm{Binomial}(k,\pi_j)$, using the existing age-dependent
per-attempt success probability. Destination states are $(n+X,m+X)$. The existing
first-birth fixed cost is paid once when $n=0$ and $X>0$. Existing first-birth and
continuation choice scales, destination child costs, timing, credit, entry,
earnings, transfers, population closure, and housing supply are retained.

The copied `model/engine/` owns the changed Bellman and forward operators.
Reporting first authenticates the frozen source and target contracts, then
installs recorded in-memory copies of the active calendar and observer functions.
Every replacement and before/after source hash is saved in
`birth_count_observer_receipt.json` under the private native case. First-birth
families remain tagged by origin $n=0$ while retaining their actual $n=1,2,3$
destination mixture. Crossed-order flows count children; ownership comparisons
count successful households once. Uniform within-period stock interpolation
remains the inherited measurement approximation; separate birth dates within a
four-year cell are not reconstructed.

Missing archived compatibility sources are recovered byte-for-byte from the
recorded Git commit into `frozen_sources/`. Its checked mapping redirects only
reads of the exact missing paths after the existing frozen overlay. Original
paths, working-tree deletions, and the original frozen manifests are preserved.
These are nonnumeric source/provenance adaptations, not changes to inputs.

## Commands

Use the authenticated local Python environment from the repository root:

```sh
export NUMBA_NUM_THREADS=1 OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1
PYTHON=output/model/publication_refactor_20260929/local_env_v1/venv313/bin/python
"$PYTHON" code/model/experiments/birth_count_choice/run.py --help
"$PYTHON" code/model/experiments/birth_count_choice/run.py --preflight
"$PYTHON" -W ignore -m unittest discover -s code/model/experiments/birth_count_choice/tests -p 'test_*.py' -v
```

`--help` is inert. Preflight authenticates and checks input propagation without
claiming any lifecycle solve. Observer adaptation is process-local; run preflight
and the actual run as separate commands, as shown here.

After review, one command runs a bounded, one-core stationary GE, including its
inherited native repeat and acceptance gates:

```sh
"$PYTHON" code/model/experiments/birth_count_choice/run.py
```

The run has a 900-second global budget, a 300-second per-lifecycle stage budget,
and at most 32 lifecycle solves. It holds $H_0=6.40569359569417$ and starts from
price $0.7760569760205563$. It writes only
`output/model/experiments/birth_count_choice/current_params_v1/`. A successful
case has the complete 14-row target table, all 31 parameter records, the standard
17 diagnostic PNGs, eight cached policy figures, seven aggregate figures, and
saved arrays/explorer assets. `latest` is published only in that experiment root.
Failed attempts remain inspectable there. No production `latest` is published.

The optional binary-cap regression helper explicitly performs **one fixed-price
partial-equilibrium solve**, rather than a GE or calibration:

```sh
"$PYTHON" code/model/experiments/birth_count_choice/check_cap_one.py --out output/model/experiments/birth_count_choice/cap_one_check
```

It first checks the saved canonical case's parameter, external-input and grid
identity, then reports every inherited saved solution array difference. Its pass criterion
is core distribution and housing-demand differences no larger than 5e-9 plus
probabilities within 2e-12 of [0,1]; it does not claim every raw array is equal. Do not run it in
parallel with another local model solve. It has a 300-second lifecycle budget.

The complete standard packet is generated by the normal run. Cached policy
figures can be regenerated without solving using:

```sh
"$PYTHON" code/model/experiments/birth_count_choice/plot_policies.py
```

That plotter defaults to the experiment's cached `latest`; `--case` pins another
completed case. Its first-birth plot displays the probability of at least one
realized birth. Standard count-aware plots use expected birth counts or correctly
weighted realized-birth probabilities. Full GE convergence and economic fit
remain unresolved until a run passes the inherited gates and its complete packet
has been inspected.

The complete converged comparison is written to
[RESULTS.md](../../../../output/model/experiments/birth_count_choice/current_params_v1/RESULTS.md).

After the lead confirms the experiment's `latest` is ready, run this no-solve
readout:

```sh
"$PYTHON" code/model/experiments/birth_count_choice/summarize.py
```

It compares exactly the canonical case
`output/model/local_solution/cases/20261003T175652812716Z_b1c72f13` with the
experiment's `current_params_v1/latest`. It refuses incomplete cases or changed
target/weight fingerprints, and verifies the ten supplied parameter coordinates
are unchanged. It writes `RESULTS.md`, `comparison.csv` with all 14 target rows,
and `parameters_comparison.csv` with all 31 parameter records, bounds and
near-bound indicators into the experiment output root. It generates no plots.

one-birth menu with the experimental menu allowing intended births from zero
through three, using the retained age-specific Binomial realization

\[

\]
with no additional factor of $R$ applied to $b'$. The timing and estate
interpretation remain unresolved pending the author's decision; the equation

If authorized after that decision, the comparison would use ten workers total:
five matched starting points per arm, with identical starts, parameter bounds,

arms. No jobs have been launched for this comparison. The SCF bequest
recipient and wealth-scope definition is still unresolved, so this proposal

`first_birth_hazard_by_age`, `fert_by_age`, and

cap-one comparison instead of counted as an economic-equivalence failure.
